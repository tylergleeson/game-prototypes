## 1. The table (`dailies.js`)

One solver-verified board per calendar day, generated by
`tools/generate-dailies.mjs` on `tools/gen-core.mjs` — the same generator, solver
and exit rule that graded the 30 shipped levels. Nothing is generated in the
page: a generator in the page is a solver in the page, and par has to be a fact
the player cannot dial.

**Seed** is the date, not a stream position: `setSeed(fnv1a('ge-daily-' + date))`
masked to the 31 bits the core's RNG uses. Every row is reproducible from its
date alone, in any order, on any machine.

**Weekday curve** — four archetypes mapped onto seven weekdays
(`WEEK = ['mid','easy','easy','mid','hard','hard','peak']`, index = UTC weekday):

| archetype | days | board | colors | blocks | stones | gate slack | excess |
|---|---|---|---|---|---|---|---|
| easy | Mon, Tue | 6×8 | 2 | 4 | 0 | 0.7 | 0 |
| mid  | Wed, Sun | 6×8 | 3 | 5 | 1 | 0.5 | 0–1 |
| hard | Thu, Fri | 6×8 | 3 | 6 | 2 | 0.4 | 1–2 |
| peak | Sat      | 7×9 | 4 | 7 | 2 | 0.2 | 1–3 |

Measured mean excess (`par − blockCount`) over the year, asserted by the bot:
Mon 0.00 · Tue 0.00 · Wed 0.13 · Thu 1.06 · Fri 1.12 · **Sat 1.15** · Sun 0.10.
The week genuinely rises to Saturday. Move limit is `par + 3` on every day.

**Encoding** — one row string, four `-` separated sections, every field a single
base36 digit:

```
'WHPM-<shape color x y>*-<color side start len>*-<x y>*'
'6847-4025414020452122-00041224-'      ← 2026-09-01, 6×8, par 4, limit 7
```

`W H P M` = width, height, par, move limit. Shape ids index
`['s1','h2','v2','h3','v3','sq','l1','l2','l3','l4']` (from `SHAPES`); side ids
index `SIDES`. **53.9 bytes/day**, and the generator round-trips all 365 rows
through the *shipped* decoder before writing, so an encoder/decoder drift cannot
survive a run. The decoder is 15 lines at the foot of `dailies.js`
(`DAILIES.index/dateAt/rowFor/decode/levelFor`), all date maths in UTC.

**Append-only.** `tools/dailies.lock` pins a SHA-256 over the frozen prefix —
every row up to and including today (`frozen: 2` right now, through 2026-09-02).
The generator re-derives that hash from the file on disk *before* it generates
anything and aborts if it disagrees; it then aborts again if regeneration would
change any frozen row. Verified by tampering one character of row 0:

```
ABORT: dailies.js frozen prefix (2 rows) does not match tools/dailies.lock.
```

Past the end of the table (or before its start) `rowFor` wraps modulo the row
count onto a row that **was** generated and verified — never an improvised board.

## 2. Proof (`tools/solve-daily-paths.mjs` → `tools/daily-solutions.json`)

Reads `dailies.js` *through its own shipped decoder* (the file is evaluated, not
re-parsed), then re-solves every row from scratch with gen-core's path-recording
A*. **365/365 rows have a line at exactly par** (slowest 170 ms). Output is
123 KB, **tool-side only** — it is a walkthrough for every board of the year, and
the bot asserts none of the three build scripts copies it anywhere.

`solveWithPath` / `reachableWithPaths` / `pathTo` moved **into `gen-core.mjs`**
so the daily solver and the level solver share one copy of the rule.
`tools/solve-paths.mjs` became a consumer (90 lines deleted, no logic change) —
this is the one file I touched outside the stated lane; `tools/solutions.json`
and `levels.js` both regenerate **byte-identical**, verified by `diff`.

## 3. Engine (`game.js`)

The draft rides on a **virtual level index**, `DAILY_INDEX === LEVELS.length`
(30). `LEVELS` never changes shape, so every consumer that keys off a level index
has exactly one question to ask (`isDaily()`) and the answer is always the same:
the draft is outside the campaign.

- `levelAt(i)` sources the board; `loadLevel` lets `DAILY_INDEX` escape the clamp
  only while a board is armed, calls `syncDailyMode()` for the draft and skips
  the `ge_level` write, and returns before the one-time tips (the draft teaches
  nothing and interrupts nothing).
- HUD label: `DAILY DRAFT · 15 Sep`, or `PRACTICE · NOT RECORDED`.
  `#hudLevel` also gets a `.daily` class for pass 4 to style.
- `win()`: `last = daily || li === LEVELS.length - 1` (the **`last` fix** — the
  draft's "next" is the way out, never `LEVELS[31]`); no `ge_best` write, no
  `ge_level` write; `daily` and `date` on the `ge:win` detail (plus `blocks`,
  which developer-r2's Field Survey handler reads).
- Retry on the draft never spends or gates on a life, at any level index, with
  the economy switched back on.
- "Back to menu" dispatches `ge:finished` with `{ daily: true, date }`, then
  restores `li`/`resumeLevel`/`ge_level` — the shared handler still does
  `GE.load(0)`, which is right after the 30th sheet and wrong after a draft.
  The restore leaves one cosmetic seam: `L` is briefly level 1's board while
  `li` is the resume level, until the next load. It resolves itself (`resumable()`
  is false at that point, so Play runs `GE.load(GE.level)` and lands correctly),
  and the bot asserts the player returns to level 13 rather than level 1.

  **Pass 4 should fix both halves together, in this order** — the menu-side
  change alone would leave the win card on screen, because `GE.load(0)` is
  currently the only thing that hides it:

  ```js
  // game.js, btnNext.onclick daily branch — load first (hides the card, restores
  // li/L/ge_level consistently), THEN hand control to the menu
  loadLevel(resumeLevel);                       // fires ge:load → menu.js show(null)
  window.dispatchEvent(new CustomEvent('ge:finished', { detail: { daily: true, date } }));

  // menu.js ge:finished — the draft has no campaign reset to do
  window.addEventListener('ge:finished', e => {
    if (e.detail && e.detail.daily) { show('menu'); return; }
    GE.load(0); show('menu');
  });
  ```

**Record (`ge_daily`)** — `{ v: 1, cur, practice, hist[≤30] }`.
`cur = { date, state:'won'|'lost', moves, par, stars, undos, hints, rescued, cleared, blocks }`.
The record opens on the first load of today's draft and **closes on the first
resolution**: a clear, or a loss the player resolved by declining the rescue —
retrying, leaving the board, or closing the page (`pagehide`). The fail sheet
alone decides nothing, because taking the rescue keeps the same attempt alive; a
rescue that leads to a clear is recorded as a fact (`rescued: true`), never
hidden. Once closed the row is never rewritten: later plays are practice, they
bump `practice.plays` and touch nothing else. A closed row from a previous day is
archived to `hist`; an attempt that never resolved was never a result and is
dropped.

## 4. FIELD REPORT (`GE.dailyShareText`)

```
GATE ESCAPE · FIELD REPORT
14 Nov 2026 · CLEARED
■■■■■■■■
★★★ · 8/8 moves · route 100%
undo 0 · hint 0
```

Loss line 4 reads `☆☆☆ · 4 of 6 out · 9/6 moves` (no route figure — it would be
meaningless). Bar is `■`×par + `□`×(moves−par), capped at 20 cells with ` +n`;
` · rescued` appends to the last line. Codepoints are ASCII plus `★☆■□·` only.

The **spoiler assertion** is the important one: every player is on the same
board, so a per-move grid would be a walkthrough. Two *different* boards played
to the same numbers must produce the same report but for the date line — the bot
asserts exactly that, plus a pinned format regex, the codepoint allowlist, five
lines, and no coordinate-shaped text.

## 5. Hooks for pass 4 (exact API)

```js
GE.loadDaily(dateStr?)   // arms + loads the draft; defaults to today. -> bool
GE.isDaily               // the draft is the board on screen
GE.dailyDate             // 'YYYY-MM-DD' of the armed draft (null before first load)
GE.dailyIndex            // 30 — the virtual level index
GE.dailyShareText(date?) // the FIELD REPORT string, or null if that day never resolved
GE.dailyInfo             // {
                         //   today, date, index, wrapped, active, practice,
                         //   par, limit,
                         //   done,      // today's record has closed
                         //   cur,       // ...and this is it (null while open)
                         //   plays,     // practice plays today
                         //   hist       // last 30 closed days, newest first
                         // }
```

Events: `ge:load` and `ge:win` details now carry `daily` (boolean) and `date`
(string on a daily, else null); `ge:win` also carries `blocks`. `ge:finished`
carries `{ daily: true, date }` when it comes from the draft. A new `ge:daily`
event fires the moment the day's record closes, with the same payload as
`GE.dailyInfo`.

All dates flow through `GE.now()`, so pass 4's checks can stand on any calendar
day without touching the system clock.

Two cosmetic leftovers in developer-r2's files, flagged not touched:
`pause()` reads "Level 31" during a draft, and the `ge:finished` handler is the
one that needs the `detail.daily` branch described above.
