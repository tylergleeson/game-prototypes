## 1. Generation: `sequence: k` / `seqCost`

The accept condition is the whole design. A board is solved **twice** — bare
(`parFree`) and numbered (`parSeq`) — and the chain is only kept if
`parSeq − parFree ≥ seqCost`. A permutation that happens to name the order the
player would have taken anyway costs nothing and is decoration, so it is allowed
exactly where the spec asks for it (`seqCost: 0`, the teaching level). Shipped `par`
is `parSeq`, graded by the spec's excess band as usual.

New in `tools/gen-core.mjs`:

| export | what it does |
|---|---|
| `chainPick(level, k)` | k block indices, colours taken **round-robin** — a 3-chain on a 4-colour board is three different hues, so the numerals read as an order across the board rather than a grouping within one colour |
| `fitChain(level, spec, opts)` | the two solves, the permutation retries, the accept condition. Leaves the level untouched on failure — no half-written chain escapes |
| `hintCost(level, opts)` | §3 — what the hint button will cost on this board |

`genLevel` branches to `fitChain` on `spec.sequence` and is otherwise the same code
path, byte for byte, that every level before Sheet 4 was generated by. **Permutations
are retried before the board is rerolled** (all `k!` of them, shuffled on the module
RNG): the same four blocks can be worth nothing in one order and three drags in
another, and rerolling would throw away a board that was already good.

`exitKind` / `meetsShape` / `cascadeSolvable` consume the constraint through the hook
r5 landed — nothing new was needed there. `spec.maxStates` is raised to 200 000 for
the chained specs and left alone everywhere else.

`parFree` is written onto the level during generation, **reported and then stripped**
before `levels.js` is written, so an unchained level's JSON is unchanged and the
engine reads only what it needs.

Stepwise, one thing at a time: **L31** teaches the rule and nothing else (chain 2,

cost together on the spike's own boards, finishing on a 4-chain worth three drags.

**Move limits are par+2 across the whole sheet** (`slackFor` extended: `idx <= 30 ? 3
: 2`), the Sheet-2+ tightening. Worth flagging for the lead: that applies to L31 too,
so the teaching level's two spare drags are exactly enough to push a numbered block
out of turn twice and still finish. I followed the plan rather than carving out an
exception, but if the critic session finds L31 punishing, `slackFor` is the one-line
knob.

Seeds: **ten appended**, never reordered. Unlike L1–30 these are not states of an
older single-seed run (there is no such run to inherit from), so they are plain fixed
constants, chosen once and frozen. Generation takes ~4m20s.

## 3. The pass-5 trap, and a real defect it caught

r5 §9.3 warned that a chain deeper than the runtime hint solver's allowance would make
the hint button **go quiet** on a shipped level. It never went quiet. What it did
instead was worse-shaped and easier to miss: **it went slow.**

The runtime solver (`game.js solveFrom`) iterative-deepens — cap = remaining,
remaining+1, … remaining+6 — and every cap *below* the answer is a complete miss that
burns its whole 80 000-state budget before widening. A board whose optimum sits three
drags above the trivial bound therefore pays for two full failed searches before the
third one answers. My first cut of L37/38/40 measured **439 ms / 1094 ms / 2513 ms**
for a single hint, against **57 ms** for the worst board on Sheets 1–3. A 2.5-second
frozen tap right after a rewarded-ad placeholder is a shipped-quality bug.

The fix is a generator gate, not a runtime change, because deterministic levels are
the product: `gen-core.hintCost()` walks the runtime's own iterative deepening (same
successor set, same admissible heuristic, same per-cap budget) and returns the node
count, and the chained specs carry `maxHintStates: 2500`. The measurement tracks the
browser closely (~18 states/ms), and the ceiling is set so no chained level answers
perceptibly slower than an unchained one:

| | worst hint, before the gate | after |
|---|---|---|
| Sheets 1–3 (unchanged) | 57 ms (L28), 981 states | — |
| Sheet 4 | **2513 ms** (L40), 44 693 states | **152 ms** (L38), 2382 states |

The gate re-runs in the bot against what actually shipped, so a future curve edit that
makes the hint expensive fails there too.

**Left for someone else, deliberately out of my lane:** `solveFrom` costs ~10 µs per
node, mostly because it allocates a fresh occupancy grid *per block per node* rather
than once per node. Building it once and masking the block's own cells would cut the
constant several-fold and give the whole hint feature headroom. That is `game.js`, so
I have not touched it — recommending it for pass 7 or 8.

## 4. Sheet 4's certification reward

`CHAPTERS` gains **'Sign-off'**; `PER` is derived, so four chapters make four sheets of
ten with no other edit.

**A naming collision, and the call I made.** The lead's decision was "a seal/stamp
cosmetic". `menu.js` already has a `SEAL_SVG`, a `.seal-ico` class and a **weekly seal**
on the Field Survey sheet — my first cut literally redefined the survey's CSS class. One
word for two different rewards is exactly how a meta surface stops being legible, so
Sheet 4's reward ships as the **Approval stamp** (`APPR_*`, `.appr-ico`), which is also
the better name: Sheet 4 *is* the approval chain, and the stamp is what signs a drawing
off. Flagging it because it is a rename against the brief's wording, not against its
intent — the reward is still one cosmetic mark, still no fourth paper.

What it is:

- **On the sheet index**, a **Stamp** shelf directly under the Paper picker — the same
  cosmetic shelf, arriving with the same disclosure gate. It is **previewable while
  pending**: the ring is drawn and the approval check is not, so the two states differ
  in SHAPE, not colour (the rule the certification stamp already follows). Like a locked
  swatch, a tap explains it (`Sheet 4 · certified at 24 ★`) rather than doing nothing;
  the resting caption reports progress (`★ 21/30 on Sheet 4`).
- **On the win card**, stamped off-square in the top-right corner, on **every** win from
  then on (draft and test boards included) — a cosmetic nobody sees again is not a
  reward. The win that earns it gets the one-shot landing animation.
- The reveal row reads `Sheet certified — Approval stamp` and carries **no Try it**:
  there is nothing to apply, so the button is removed rather than left as a dead control.
- Drawn in `currentColor`, so it inherits every paper instead of adding a theme — no new
  tokens, no new contrast rows, which was the point of the lead's decision.
- `revealCert` now takes the **sheet**, not a skin id; `prog.appr` is the one new saved
  byte, retro-unlocked for a save that already clears the threshold, and it lapses with
  the stars on Reset exactly as the papers do. `cert_earned` gains `{ stamp: true }`.

The legend's approval-chain row needed nothing: its gate is derived from the shipped
levels (`LEVELS.some(l => l.blocks.some(b => b.seq))`), so Sheet 4 turned it on by
itself — the bot check r5/r4 left in place asserts exactly that.
